# Spec: process-gpt-document-parser

출처: [intent.md](intent.md) (2026-10-16 수락). 측정 근거: [VERIFICATION.md](VERIFICATION.md).

## 요구사항

1. `parse(source, *, filename=None, describe=None, ocr=None, max_workers=4) -> Document`.
   `source` 는 경로 또는 bytes. 포맷은 내용(시그니처)으로 고르고 확장자는 오류 메시지에만 쓴다.
2. 지원: HWP 5.0(배포용 포함), HWPX, DOC(Word 97 이후), DOCX, PDF.
3. 모든 포맷이 같은 출력 구조를 낸다(아래 "출력 모델").
4. 그림 설명·OCR 은 콜백. 라이브러리는 모델·네트워크를 부르지 않는다.
5. 오류는 세 가지로만 낸다: `UnsupportedFormatError`, `EncryptedDocumentError`, 그 밖의 망가진 파일은
   `ParseError`(내부 struct·index 오류도 감싼다). 모두 `ParseError` 의 하위 클래스.
6. 의존성은 허용형 라이선스만. 기본 설치는 `olefile` 하나, PDF 는 `[pdf]`, 배포용 HWP 는 `[hwp-distribution]`.
7. HWP·HWPX·DOC·DOCX 는 외부 실행 파일·다른 파서 라이브러리 없이 읽는다.

## 출력 모델 (`model.py`)

- `Document`: `format`, `blocks`, `page_sizes`(PDF 만), `metadata`(`filename`, 배포용 HWP 는 `distribution`), `warnings`.
- `Block`: `kind` ∈ paragraph·table·image, `text`, `heading_level`(1부터), `table`, `image`, `page`(0부터, PDF 만),
  `bbox`(PDF pt, 왼쪽 위 원점), `comments`(DOCX 메모), `ocr`(OCR 콜백이 만든 글).
- `Table.cells`: `Cell(text, row, col, row_span, col_span)`. 병합 정보를 잃지 않는다.
- `Image`: 원본 bytes·mime·`description`.
- 블록 순서 = 문서 읽기 순서.

## 공통 동작

- 머리말·꼬리말은 본문에서 뺀다. 글상자·캡션 글은 앵커 자리에 넣는다.
- 각주·미주: HWP·HWPX 는 앵커 자리에 글을 넣고, DOC·DOCX 는 뺀다(포맷 간 불일치, 아래 "우려").
- 표 칸 안 여러 문단은 칸 글 안에서 띄어 잇는다(붙이면 `422`·`423` → `422423`).
- 그림 블록은 그 그림이 든 문단·표 뒤에 온다.
- 그림 설명(`describe`): 같은 바이트 그림은 한 번만 부르고 설명은 처음 자리에만. 짧은 변 80px 미만은 부르지 않는다.
  콜백 실패는 빈 설명으로 두고 파싱은 계속한다. 빈 설명인 그림 블록은 마크다운에 아무것도 내지 않는다(로고 건너뛰기).
  설명은 `[그림: ...]` 으로 그 자리에 들어가므로, VLM 이 그림 속 표·글·값을 옮기면 문서 정보가 된다(BENCHMARKS "문서 속 그림").
- `Document.to_markdown(table_format=)`: `markdown`(기본, 병합 칸 값을 덮인 칸마다), `markdown-first`, `html`.
  `html` 의 칸 안 줄바꿈은 ` <br>`(태그를 지우고 읽어도 줄 사이 낱말이 붙지 않게).

## 포맷별

**HWP 5.0** (`formats/hwp.py`, 한컴 공개 명세)
- FileHeader 속성: 압축(bit0), 암호(bit1 → `EncryptedDocumentError`), 배포용(bit2 → `ViewText/Section*` 를
  `DISTRIBUTE_DOC_DATA` 로 얻은 AES-128 키로 복호화, `cryptography` 필요).
- 레코드 트리: 문단(PARA_HEADER) 아래 PARA_TEXT·CTRL_HEADER. 확장 컨트롤 글자는 CTRL_HEADER 와 같은 순서로 짝짓는다.
- 표 `tbl `: 칸 LIST_HEADER 의 열·행·병합. 캡션은 표 뒤 문단. `head`/`foot` 은 건너뜀.
- 헤딩: DocInfo PARA_SHAPE 의 개요 문단(속성 bit23-24 = 1, 수준 bit25-27).
- 그림: SHAPE_COMPONENT_PICTURE 오프셋 71 의 BinData 번호 → DocInfo BIN_DATA → `BinData/BIN%04X.ext`.
- 출력은 같은 문서의 HWPX 출력과 같아야 한다(시험으로 고정).

**HWP 3.x** (`formats/hwp3.py`, `hwp3_chars.py`, 한컴 「한글 문서 파일 형식 3.0」) — 한글 97 이하. OLE 가 아닌 단일 파일
(서명 `HWP Document File V3.00`)이라 `detect_format` 이 따로 알아보고 `hwp.parse` 가 넘긴다. `metadata["hwp_version"] = "3.x"`.
- 문서 정보 오프셋 96 암호 여부(≠0 → `EncryptedDocumentError`), 124 압축. 압축 본문은 raw deflate(zlib wbits −15).
- 글꼴 이름(언어 7개) → 스타일 → 문단 리스트 → 추가 정보 블록(id 1 = 삽입 그림: 이름 16 + 포맷 16 + 자료).
- 명세에 없고 실측한 것: 리스트 끝 빈 문단은 43바이트(문단 모양 없음). 글자 수는 hchar 단위로, 고정 길이 특수 문자는
  자료까지, 표·그림·각주 같은 문단 리스트 특수 문자와 예약 형식은 식별 정보(4 hchar)까지만 센다.
- 표(특수 문자 10, 박스 종류 0): 셀 위치·크기(hunit)로 격자선을 정한다. 10 hunit(0.14mm) 안의 경계는 같은 선
  (셀 좌표에 1~3 hunit 반올림 오차가 있다). 텍스트박스·버튼은 글을 제자리에, 수식(종류 2)은 스크립트를 내지 않는다.
- 그림(11): 삽입 그림(종류 2)은 이름으로 추가 정보 블록의 자료를 찾는다. 그리기 개체(3)는 글상자 문단 리스트 글만.
  캡션 글은 제자리에. 각주·숨은 설명은 제자리에, 머리말·꼬리말은 뺀다(HWP 5.0 과 같다).
- 헤딩: 특수 문자 28(개요 번호)의 단계 + 1. 개요 문단이 든 샘플이 없어 검증하지 못했다.

**HWP 3.x 글자 코드** (`hwp3_chars.py`) — 명세는 hchar 를 "한글 설명서 참조"로만 남겼다. 한컴이 같은 문서를 HWPX·HWP5 로
바꾼 본(rhwp 샘플 9쌍)과 맞대어 정했다.
- 0x0000~0x007F ASCII, 0x8000 이상 상용 조합형 한글(KS X 1001 부속서 3, `johab` 코덱).
- 0x3400 + (행−1)×0x60 + 열: KS X 1001 기호 행. 맞대어 확인한 1·2·3·5·6·8행만 쓴다(11행 자리에서 가타카나가 아닌
  괘선이 나왔다).
- 0x4000 + 순번: KS X 1001 한자 4,888자 순서. 독음이 다른 중복 한자는 호환 영역 글자 그대로(한컴 변환본과 같다).
- 0x2000~0x22FF 는 유니코드 값 그대로(0x2022 •, 0x2219 ∙ 로 확인).
- 낱개로 확인한 코드: 0x81~0x84 “ ” ‘ ’, 0x2F11 ◦, 0x3404 ․, 0x340D ～, 0x37ED ═ (가운뎃점·물결은 KS X 1001 표준 대응
  U+00B7·U+223C 대신 한컴이 고른 글자).
- 나머지(한컴 고유 기호 영역 0x2C00~0x33FF 등)는 U+FFFD 로 두고 `warnings` 에 개수·코드를 남긴다. 한컴 변환본도
  이 글자들 대부분을 사용자 정의 영역(PUA) 글자로 낸다.

**HWPX** (`formats/hwpx.py`, KS X 6101) — `section*.xml` 을 번호 순으로. 개요 수준은 header.xml paraPr heading.
암호(META-INF/manifest.xml 의 encryption-data) → `EncryptedDocumentError`.

**DOC** (`formats/doc.py`, MS-DOC·MS-ODRAW)
- nFib < 0xC1(Word 6/95 이전) → `UnsupportedFormatError`. fEncrypted → `EncryptedDocumentError`.
- 본문 = 피스 테이블(Clx)의 cp 0 ~ ccpText. 필드는 결과만 남기고 명령은 버린다.
- 표: PAPX 의 fInTable·fTtp·itap, 병합은 TDefTable(가로 경계·TC 병합 비트)과 sprmTVertMerge.
  칸·행 끝 표시 없이 끝나는 표도 쌓인 글을 버리지 않는다. 중첩 표는 바깥 칸 글로(`a | b / c | d`).
- 헤딩: sprmPOutLvl, 기본 제목 스타일(sti 1~9), 스타일 개요 수준, istdBase 상속.
- 그림: 인라인은 CHPX 의 sprmCPicLocation → Data 스트림 PICF·OfficeArt blip. 떠 있는 그림·글상자는
  PlcfSpa(도형 id) → DggInfo 의 FSP·FOPT pib → BStore, PlcftxbxTxt.

**DOCX** (`formats/docx.py`, ECMA-376) — 메모 앵커 글, 헤딩 스타일 basedOn 상속, gridSpan·vMerge, 콘텐츠 컨트롤(sdt).

**PDF** (`formats/pdf.py`, `pdf_layout.py`, `pdf_subrows.py`, `pdf_objects.py`)
- 선·사각형·곡선은 pdfium 으로, 글자·그림은 경로 명령을 걷어 낸 내용 스트림으로 pdfminer 가 읽는다. 칸 클립은 원래 스트림에서
  읽는다. 출력은 pdfminer 로 다 읽은 것과 같아야 한다(돌린 쪽은 pdfminer 만).
- 쪽 밖(가운데가 쪽 상자 밖)에 놓인 글자는 버린다(펼친 면에서 잘라 낸 쪽에 옆 쪽 글이 남아 있다).
- 글자는 콘텐츠 스트림 순서로 줄 → 블록으로 묶고, 쪽 안 읽기 순서는 위치로 정한다(XY-cut):
  - 블록·표를 위아래로 겹치지 않는 가로 띠로 자른다. 이어지는 띠들이 어느 블록도 건너지 않는 단 사이 틈을 함께 가지면 한
    묶음으로 보고 단(왼쪽부터)으로 읽는다. 한 단뿐인 묶음은 다음 띠의 단 틈을 막지 않으면 그 단의 윗부분이다.
  - 한 줄짜리 블록 여럿이 늘어선 띠(머리말 줄, 이름 | 값)는 행으로 읽는다. 블록이 모두 20자 넘는 글이면 행이 아니다.
  - 묶음 가로 범위 밖에만 있는 띠, 묶음 바닥에서 두 줄 넘게 떨어진 마지막 블록(각주·꼬리말)은 묶음에 붙이지 않는다.
  - 어느 쪽으로도 안 갈리면(겹친 블록) 스트림 순서 그대로.
- 띄어쓰기를 공백 글자로 담는 문서(공백 글자 ≥ 글자 수 5%, 문서 단위)는 간격만 보고 띄어 쓰지 않는다. 단 줄의 보통 글자
  간격(중앙값)보다 0.2em 넘게 더 벌어진 틈은 띄운다(공백 글자 없이 찍은 양쪽 정렬 줄. 균등 배분은 모든 간격이 함께 벌어진다).
- 글꼴 ToUnicode 가 U+FFFD 로 적은 글자는 인코딩 글리프 이름으로 풀고, 작은 대문자 글리프(.smcp·.c2sc)는 대문자로 낸다.
- 글자 정리(pdfplumber 표 추출도 같은 글자를 본다): 합자(ﬁ·ﬂ 등)를 풀고, 기본 글자 위에 겹쳐 따로 찍힌 발음 기호(˜ ˆ ¨ 등)는
  그 글자와 합친다(겹치지 않는 ´ 는 따옴표로 둔다). 블록 안에서 줄 끝이 `글자-` 이고 다음 줄이 소문자로 시작하면 낱말을 붙인다.
- 표: pdfplumber `find_tables` 후 찾은 표의 바깥 틀을 가상 선으로 닫고 다시 찾는다. 바깥 세로선이 없으면 표 행을 가로지르는
  가로선이 뻗은 데까지 틀로 본다. 표의 열 세로선 둘 이상이(칸마다 끊어 그린 조각은 이어서, 쪽 높이 80% 넘는 변은 빼고)
  표 위아래로 더 뻗고 그중 안쪽 열 선이 하나 이상이면 거기까지 표다(윗선 없는 머리행, 아랫선 밑 합계 행). 늘린 쪽에서 짧게
  그친 열 선은 그 자리에 글이 없거나 1em 넘게 벌어진 자리일 때만 끝까지 잇는다(병합 머리칸은 그대로).
  - 위아래 좌표가 0.5pt 안에서만 다른 선은 가로선이다(pdfplumber 는 세로선으로 분류한다).
  - 선 친 표 바로 위(1.5em 안), 위아래 선 없이 놓인 한 줄이 1em 넘는 간격으로 덩어리 둘 이상으로 갈리고 덩어리마다 표의 한 열
    안에 들면 머리행이다(그 위 1.5em 안에 다른 글이 붙어 있으면 아니다). 덩어리를 가르지 않는 열 경계에 세로선을 긋는다.
  - 줄무늬 행: 폭이 같은 표 조각 사이 간격이 칸 높이 중앙값의 1.5배 이하이고 그 틈에 글(배경 없는 행)이 있으면, 두 조각이
    함께 쓰는 열 경계를 틈에 그어 한 표로 잇는다.
  - 칸 클립 묶음이 쪽 절반보다 넓으면 한 열짜리 표(줄 음영 글 상자)는 그 묶음으로 넓히지 않는다.
  - 표가 아닌 격자: 한 행짜리인데 첫 칸이 그림 제목(Figure·Diagram·Chart·그림·도표 등 + 번호)인 것, 글자 없이 숫자만 든 칸이
    격자 칸의 절반 이하인 것(막대그래프 위 숫자), 칸 안 글자 대부분이 누운 것(그래프 축 날짜), 차례(열 셋 이하, 끝 열이 모두
    세 자리까지 쪽 번호로 줄지 않고 앞 열은 글. 칸 하나에 줄로 쌓였어도 줄마다 본다).
  - 한 열 표는 세 행 이상이 모두 글을 담고 행 사이마다 보이는 가는 선(선·테두리·2pt 이하 채움)이 표 폭 80% 넘게 가로지를
    때만(칸 친 목록). 같은 색 줄 음영이 맞붙은 글 상자는 아니다.
  - 글 없는 1.5em 미만 폭의 칸은 다른 행이 쓰지 않는 경계 쪽 옆 칸에 붙인다(칸 배경과 선이 조금 어긋난 자리). 다른 행도 쓰는
    경계 사이의 빈 칸(들여쓰기 열)은 그대로.
  - 점선 괘선: 1pt 미만 선분이 한 축에 3pt 이하 간격으로 5개 이상 늘어서면 선 하나로 잇는다(pdfplumber 는 1pt 미만 선분을
    잇기 전에 버린다). 길이 0인 점(둥근 끝으로 찍은 점선)은 늘어선 방향으로 잇는다.
  - 가로선만 있는 표(논문식 세 줄 표): 같은 높이 선 조각을 잇고, 쪽 폭 20% 넘는 가로선이 3개 이상 겹쳐 늘어서며 그 사이 띠의
    글이 열로 갈리면(1em 넘는 간격으로 덩어리가 나뉜 줄이 절반 이상, 덩어리 둘이 모두 표 폭 35% 넘고 20자 넘으면 2단 본문이라
    빼고) 표다. em 은 쪽 글자 크기 중앙값이고, 줄 글자가 그보다 작으면 그 줄 글자 크기. 열로 안 갈리는 띠(캡션·주석)에서 표를
    끊는다. 단 맨 위 띠가 한 줄이고 다음 띠가 열로 갈리면 그 줄은 제목칸(병합)이다. 머리 일부 열에만 그은 짧은 선도 그 표의
    선이고, 표 폭은 그 표(끊긴 띠 사이) 선 중 가장 넓은 선. 안쪽 선은 양 끝을 1em 안의 가장 가까운 열 경계까지 늘린다
    (cmidrule 은 끝을 조금 줄여 그린다). 위아래 선 안쪽에 통째로 든 찾은 표(배경 칠한 강조 행)는 이 표의 행이고, 강조 행이
    그린 세로 변이 열 빈자리에 있으면 그 자리를 열 경계로 쓴다. 칸 하나짜리 찾은 표(제목 띠 배경)는 겹쳐도 막지 않는다.
  - 위·아래 선 둘뿐인 표: 그 사이 줄이 셋 이상이고 열로 갈리며, 두 선이 세로 변으로 이어진 상자(그래프 틀)가 아니면 표.
    행은 줄 사이가 줄 높이 중앙값의 절반 넘게 벌어진 자리이고, 열 선은 행마다 따로 긋는다. 맨 위 행이 열로 안 갈리면
    (제목) 열 자리를 정할 때 빼고 병합 칸으로 둔다.
    열 경계는 줄이 가장 많은 띠의 줄들이 3줄 이상 함께 갈리는 빈자리(띠마다 한 줄뿐이면 모든 띠의 줄이 함께 갈리는 자리).
    그 빈자리 안에서 본문 바로 위 띠(열 이름 줄)의 글 덩어리, 낱말 간격의 2.5배 넘게 떨어진 덩어리, 다른 띠의 글 덩어리 순으로
    가장 적게 가로지르는 곳에 둔다. 띠마다 그 자리를 가로지르는 낱말이 없을 때만
    긋는다(여러 열에 걸친 머리는 병합 칸, 맞붙은 글자 사이는 낱말 안). 격자로 이미 찾은 표 자리는 뺀다.
    본문 위 머리 띠에 위아래로 겹치지 않고 가로로도 겹치는 덩어리가 없는 줄이 여럿이면(층층이 쌓인 묶음 머리) 줄마다 행으로
    가른다. 열보다 덩어리가 적은 줄은 제목 띠처럼 위아래 선 끝 자리에서만 나누고, 첫 열에 이름이 하나뿐이면 그 칸은 머리
    층 전체에 걸친다.
  - 선 없는 본문: 표 안에서 시작한 세로선이 표 아래 표 폭 가로선까지 이어지면 표는 그 가로선까지다. 머리행 맨 아래 칸들의
    열 경계를 그 가로선까지 가상 선으로 내리고, 행은 하위 행 나누기가 글 줄로 가른다.
  - 테두리 없는 채움 사각형 중 좌우나 위아래 양쪽이 다른 선·사각형에 맞닿지 않은 것(칸 안에 뜬 글자 음영)은 표 선에서 뺀다.
    배경색 칸끼리 맞붙어 칸을 이루는 표는 남는다. 한쪽만 맞닿아도 같은 높이 채움 칸과 세로 변을 나눠 붙었으면(바깥 테두리 없는
    줄무늬 행의 가장자리 칸) 남긴다. 더 큰 채움 사각형 안에 좌우 또는 위아래로 들여 그린 채움 사각형(Word 가 칸 배경 안에
    줄마다 그리는 문단 음영)과 더 큰 채움 사각형 안에 같은 색으로 그린 것은 서로 맞닿아도 뺀다.
  - 다른 칸 안에 통째로 든 칸(칸 안 점선 상자)은 빼고 바깥 칸을 하위 행 나누기에 맡긴다.
  - 칸 클립 중 이미 찾은 칸의 같은 방향 변에서 1pt 넘게, 글 한 줄 높이(0.8em) 미만으로 들어온 변(Word 칸 안 글 영역)은
    칸 경계로 쓰지 않는다.
  - 선 없는 표: 한 블록에 여러 높이의 줄이 묶였고 높이마다 옆으로 늘어선 칸이면 행마다 나눠 보고, 표가 안 되면 블록 그대로 둔다.
    끝 칸이 모두 쪽 번호이고 위에서 아래로 줄지 않는 것(차례), 모든 행 첫 칸이 글머리 기호(•, -, 1., a))인 것(목록)은 표가 아니다.
  - 선(채움 칸)으로 그린 1행 표 바로 아래(그 행 높이 두 배 안)에 같은 칸 수의 선 없는 표가 이어지면 머리행으로 붙인다.
  - 클립 칸: 한컴·Acrobat PDF 는 표 칸마다 그 칸 사각형으로 클립을 걸고 글을 그린다. 그리기 명령에서 축에 나란한 사각형
    클립을 모아(q/Q·cm 추적) 변을 맞대고 붙은 것끼리 묶는다. 서로 떨어진 클립(글 둘레에 건 클립)과 쪽 절반 넘는 클립은 버린다.
    찾은 표에 닿는 묶음만큼 표를 넓히고(표를 통째로 감싸는 칸이 든 묶음은 빼고) 묶음 칸의 변을 가상 선으로 넣는다.
    선 없는 칸 경계·하위 행·바깥 테두리 없는 첫 열이 원본 칸대로 나온다.
  - 숨은 칸 경계: 같은 열 칸들의 글이 1em 넘는 간격(공백 글자는 빼고 보이는 글자 사이)으로 갈린 자리가 3줄 이상 겹치고,
    선이 지날 범위의 어느 줄 글자도 그 자리를 가로지르지 않으면 가상 세로선(값 | (증감), 전체 | 남 | 여, 이름 | 값).
    글머리표(기호 하나) 뒤 간격은 세지 않는다.
    선은 모든 줄 글자를 피한 빈자리에 긋고, 빈자리에 다른 행의 열 경계가 있으면 그 자리(가는 가짜 열 방지). 간격 없이 붙어
    찍힌 값(85.4100.3)도 그 자리에서 갈린다. 균등 배분 한글(한 글자 덩어리)이 든 칸은 세지 않고, 범위 안에 있으면 긋지 않는다.
    선을 넣은 표에서 다시 찾는다(최대 3번, 넣은 경계 안의 다음 경계).
  - 여러 열에 걸친 칸의 글이 열 수만큼 짧은 값(띄어쓰기 없음, 15자 이하)으로 갈리고 덩어리마다 제 열 안에 들면 열마다 나눈다.
    띄어쓴 덩어리나 열 경계를 조금 넘는 덩어리(선 없는 머리칸)는 두 줄 이상이 열마다 같은 자리(왼끝·가운데·오른끝 중 하나가
    2pt 안)에 맞춰졌고 덩어리 가운데가 제 열 안일 때만.
  - 글 틀 격자(슬라이드에서 내보낸 표): 찾은 표 밖에서 글을 담은 선 없는 채움 사각형이 같은 가로 범위로 3열 이상(열마다 3개
    이상), 여러 열이 같은 높이(3pt 안)에서 시작하는 행이 3개 이상이면 열 사이·행 사이에 가상 선을 긋는다. 행 경계는 열마다
    따로 그어 여러 행에 걸친 틀(병합 칸)은 자르지 않는다. 괘선은 배경 그림이라 보지 않는다.
  - 칸 글: 공백 글자는 그대로 띄우고, 공백 글자 없이 0.2em 넘게 벌어진 자리도 띄운다(em 은 쪽 글자 크기와 그 줄 글자 크기 중
    작은 것). 단 양쪽이 한 글자짜리 글자(균등 배분
    "투 자 액", "S S M")이거나 한쪽이 기호 하나(-, ·)면 붙인다. 한글을 줄마다 한 글자씩 세로로 쓴 칸은 붙인다.
  표 소유는 줄 단위: 가운데가 표의 어느 칸 안인 줄만 표의 몫.
- 괘선 없는 표: 같은 높이에 옆으로 늘어선 행이 3개 이상, 칸 수·가로 범위가 맞으면 표. 글이 그대로 담길 때만 바꾼다.
  빈 칸이 있어 칸이 적은 행도 칸마다 겹치는 열이 하나씩이고 첫 칸이 첫 열이면 이어진다(빈 자리는 빈 칸).
  바로 위(행 간격 안) 한 줄이 칸으로 안 갈렸어도 낱말을 열 시작에 맞춰 나눌 수 있으면 머리행이다: 열마다 첫 낱말이 앞 열 글이
  끝난 뒤, 그 열 왼끝에서 한 줄 높이 안에서 시작해야 한다. 표 제목 문단 끝에 붙어 한 블록이 된 머리 줄(옆으로 늘어선 칸)은
  떼어 보고, 표가 안 되면 블록으로 되돌린다.
  탭 정렬 표: 한 블록에서 머리 한 줄(낱말 간격으로만 띄움) 아래 값 행들의 칸(3칸 이상)이 모두 머리 낱말 첫 글자와 같은 x
  (0.5pt 안)에서 시작하면 그 자리에서 머리를 칸으로 가르고, 값 행이 하나여도 표다.
- 하위 행: 여러 행에 걸친 칸으로 이어진 행 묶음 단위로 글자 줄을 나눠 행을 만든다. 나누지 않은 행의 병합 칸은 그대로
  두고(글자 없는 복사본 행이 빠진 만큼 줄여), 하위 행으로 나뉜 행에 걸친 병합만 칸마다 채운 글로 둔다.
  - 묶음 안에 숫자가 두 줄 이상 쌓인 칸이 있을 때만 나눈다. 행 이름 글만 두 줄로 접힌 묶음(칸 클립으로 이미 갈린 계/남/여)은
    그대로 둔다. 숫자가 쌓인 열이 둘 이상이면 40자 넘는 이름이 있어도 문단으로 보지 않는다.
  - 이름만 있는 줄이 값 줄만큼 있으면 나누지 않는다(줄바꿈된 이름 옆에 값/(비중)을 쌓은 칸). 첫 값 줄 위에 몰린 이름 줄
    (묶음 소제목)은 이때 세지 않는다.
  - 나눈 결과는 값 줄 대부분(3/4 이상)이 비슷하게 차 있어야 쓴다(값을 비운 행 몇 개는 괜찮다).
  - 값 줄마다 제 이름이 있을 때 첫 값 줄 위에 몰린 이름 줄(묶음 소제목)은 이름에 붙이지 않고 값 없는 제 행으로 둔다.
  - 줄 글자 사이 틈이 글자 높이의 0.12 를 넘으면 칸 글에 띄어쓰기를 넣는다(Head Start).
- 고정폭 글자 표(공백 글자로 칸을 맞춘 타자기식): 고정폭 줄 끝에 이어진 숫자 덩어리가 셋 이상이고, 그 오른쪽 끝이 세 줄 넘게
  같은 자리(글자 반 칸 안, 줄의 60% 이상)에 오면 숫자 열이다. 앞은 행 이름(점 채움 포함). "-----" 구분 줄은 사이에 껴도 된다.
  열에 안 맞는 숫자는 가장 가까운 열에 넣고, 10% 넘게 안 맞으면 표가 아니다. 선·클립으로 찾은 표 자리에는 만들지 않는다.
  - 글자 덩어리는 그 줄이 든 행에 실제로 있는 칸 경계에서만 끊는다(병합 칸 "2018년" 을 다른 행의 경계로 자르지 않는다).
    병합 이름 칸에 덩어리가 하나면 걸친 열마다 채운다. 값은 제 열에만.
  - 이름 열은 값 줄 절반 이상에 숫자 아닌 글이 있는 열과 숫자가 드문 앞 열. 이름 | 값 이 번갈아 와도 된다.
    값 줄 절반 이상에 제 이름이 있으면, 이름만 있는 줄 묶음(줄바꿈된 이름)을 가장 가까운 값 줄 하나에 붙인다.
  - 한 글자씩 줄에 걸친 세로쓰기 이름은 한글일 때만 붙인다(한 자리 값은 그대로).
- 쪽을 넘긴 표: 앞 쪽이 열 수가 같은 표로 끝났으면 머리행을 다시 붙인다.
- 3쪽 이상 문서에서 쪽 위·아래 10% 안 글이 max(3, 쪽 수/2) 쪽 이상 되풀이되면(숫자 무시) 머리말·꼬리말로 뺀다.
- 그림: 붙어 있는 그림 자리를 영역으로 묶어 영역마다 렌더(200dpi). 쪽 1% 미만·95% 이상 영역은 뺀다.
  5쪽 이상 문서에서 같은 자리 그림이 절반 이상 쪽에 나오면 로고로 보고 뺀다. 영역이 쪽 50% 이상이면 `ocr` 로 받아쓴다.
  `describe` 를 안 주면 그림을 렌더하지 않는다(그림 블록 없음).
- 글 레이어가 없거나 깨진 쪽(글꼴 대응표 없음)은 쪽 전체를 `ocr` 에 넘긴다.

## 결정과 근거

| 결정 | 근거 |
|---|---|
| PyMuPDF 대신 pdfplumber+pypdfium2 | AGPL 회피. 품질은 memento 이상(VERIFICATION "PDF") |
| HWP·DOC 직접 구현 | "자체 기술"의 근거. 같은 문서 HWPX·DOCX 와 출력 일치로 검증 |
| HWP 3.x 글자 코드는 맞대어 확인한 영역만 바꾸고 나머지는 경고 | 명세에 코드표가 없다. 추측으로 채우면 틀린 글자가 조용히 섞인다 |
| 표 소유를 블록이 아니라 줄·칸 단위로 | 표 밑 각주가 표 블록에 묶여 버려졌다(잃은 낱말 173 → 2) |
| 표 바깥 틀을 닫고 다시 찾기 | 바깥 세로 테두리 없는 공공 문서 표에서 가장자리 열이 사라졌다 |
| 하위 행을 행 묶음 단위로 | 값 열만 행마다 선이 있으면 큰 칸이 행마다 복사됐다(국세수입 표 prec 0.571 → 0.972) |
| 표 기본 출력은 병합 칸 값을 채운 마크다운 | 표 76개·질문 280개: Qwen3.8-27B-FP8 94.6% vs HTML 90.7%(p=0.027), luna 99.6% vs 98.6% |
| 모델 호출은 콜백 | 라이브러리가 모델·키·네트워크에 묶이지 않게 |
| 표 찾기·구조에 모델·LLM 을 쓰지 않음(레이아웃·표 구조 콜백은 2026-10-23 뺌) | 규칙 강화 뒤 한국 표에서 모델 모드 -1.7~+0.2%p, AI 모드는 맞는 표를 바꿔 문항을 잃었다(VERIFICATION "AI 모드·모델 모드 뺌") |
| datalab 모델(marker·surya·chandra) 안 씀 | 가중치가 매출·투자 500만(chandra 200만) 달러 한도·경쟁 금지 조건의 수정 OpenRAIL-M |
| Camelot 안 씀 | 한국 표 효과 0, 그냥 붙이면 본문 다단을 표로 잡아 olmOCR 다단 71→34%. 레이아웃 영역 안에서만 받아도 olmOCR 표 +4.7%p 에 시간 6배(VERIFICATION) |
| PDF 글자 정리는 규칙으로 | 규칙은 비용 없이 olmOCR 다단 +15%p(holdout). 모델은 olmOCR +21%p 지만 한국 표는 0~2.5%p, torch·GPU 필요(VERIFICATION "PDF 격차 줄이기") |

## 하지 않는 것

Word 6/95·Word 2, 암호 해제, 수식을 글로, 벡터 차트 설명, 문서 쓰기·변환.

## 우려

- 각주 처리가 포맷마다 다르다(HWP·HWPX 는 본문에 넣고 DOC·DOCX 는 뺀다). 한쪽으로 맞출지 정해야 한다.
- PDF 는 문단 간격이 줄 간격과 같으면 문단이 나뉘지 않는다.
- 큰 병합 칸이 많은 서식은 기본 표 출력이 글을 크게 부풀린다(정답률은 서식으로 재지 않음).
- MS Word 가 저장한 DOC 의 표·그림 구조는 텍스트 비교(LibreOffice 대비)로만 확인했다.
